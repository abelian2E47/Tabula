# 拖动与吸附：手感是怎么改的

这份文档说明「拖动生硬、有时候吸不上去」这一轮到底改了什么，以及每一处的理由。
涉及的文件只有三个：`src/layout/grid.ts`、`src/board/Board.tsx`、`src/styles/board.css`。

## 1. 抬起来的磁贴不再拖着一根橡皮筋

`.plate` 上有一条 180ms 的位置过渡（`left/top/width/height`），它是**落位**用的：松手之后磁贴滑进格子里，看起来像磁铁吸住。
问题是这条过渡对「正在被拖的那一块」也在生效，于是磁贴永远慢指针六分之一秒，手感就成了「指着它走」而不是「拿着它走」。

现在 `.plate--dragging` 把这条过渡关掉（`transition: none`），只保留磁贴自身的拾起动画（`transform`、阴影的过渡还在），
并在拖动期间抬到 `z-index: 30`，从别的磁贴上面走过。
于是：按住的一瞬间它就在指针底下，松开的一瞬间它才开始滑。

## 2. 拖动时自由浮动，松手才落格

原来拖到一半就有个「目标格」跟着指针跳：磁贴本身跟着手走，但落点预览一格一格地跳，
而且落点还带黏性（走过下一格三分之二才换格）。看起来就是「一直在自动吸附」。

现在拖动期间磁贴跟着指针自由浮动（像素级，走一格的一半就是一半），格子背景只是铺在底下作参考；
**唯一一次吸附发生在松手**——落点是松手时指针下方的那个格子，就近取整（不到半格原地不动，过半格前进一格），
整块选区的位移同样按整数格取整。

但「自由浮动」不等于「没有预告」：手底下那块磁贴飘着，落点得让人看得见。
所以落点位置画一块**影子**（`.drop-target`）——不是磁贴的复制品，而是那一格地上的一层浅色影子，
带柔和的描边和外发光；它自己带 `left/top` 过渡，指针从一格挪到下一格时影子**滑过去**，
而不是生硬地跳过去（跳一下会被看成「换了一块影子」，滑过去才被看成「同一块影子在动」）。
落点无路可走时同一块影子变灰（`.drop-target--refused`）、取消过渡跟着指针走，并抬到磁贴之上——
这时它要说的事情正是关于周围那些磁贴的（这一格已经有人了）。

这样「手在哪、东西就在哪」和「会落到哪个格子」是两件事，中间由这块影子连着。

## 3. 松手时以指针为准，而不是以画面为准

拖动过程中的落点预览是**按帧**算的（`requestAnimationFrame` 合并同一帧里的多次 `pointermove`，避免一帧渲染十次）。
落点本身也是在这一帧里存进一个临时变量的，而这个变量**画完就被清空了**——于是：

- 快拖：手指不停，每次移动都重新填上这个变量，松手时它还热着，落点正常。
- 慢拖：指针停下来，最后一帧已经把它清空，松手时**没有落点可提交**，磁贴就回到原位——
  也就是你看到的「视觉上已经对齐，松手却回弹」。

现在指针位置存在帧循环之外的 `last` 里（每次 `pointermove` 都写，谁也不清它），
松手时用它算落点。预览和落点用的是同一个函数、同一个位置，两边不会再各说各话。

## 4. 摆出去的东西不该继续占着格子

搜索栏可以「先不显示」，收起来的栏还在存档里，位置也还在。问题是**占位判定把它算作还在板上**：
`platesOf` 只跳过了收进文件夹的磁贴，没收起不显示的。于是一条藏起来的 8 格宽搜索栏
仍然挡着它下面那一整行，旁边的搜索栏因此怎么拖都「无处可落」，松手就弹回原位；
重排逻辑甚至会为了避开它把别的磁贴推走。

现在 `platesOf` 同时跳过 `folderId` 和 `hidden`：不在板上的东西不占格子，也不参与落点判断。

## 5. 拖完的那一下不许被当成点击

浏览器在按下与松手之间无论发生了什么，都会在松手后补一个 `click`。
拖完一块磁贴，这个 `click` 会落在**指针当时所在的那个东西**上——可能是另一块磁贴，也可能是
搜索栏上被当作把手的那颗引擎图标（那会顺手把引擎面板打开）。

现在只要这次按下移动过，就会在捕获阶段吃掉紧随其后的那一个 `click`，并且只吃一个：
一次手势只吞掉属于它自己的那一下。

## 6. 拖出来的格子线要和格子本身同源

拖动时铺的网格背景原来相对画布原点偏了 `label-strip + 10px`，
于是磁贴明明在格子里，看上去却像卡在两条线中间。现在网格层的 `inset` 是 `0`，
格子和格线共用同一个原点（这一条同时修掉了「图标没落在网格上」的显示问题）。

## 7. 顺手修掉的相邻问题

- **选区批量改配置**：框选之后在任意一个被选中的磁贴上右键，设置会一起落到整个选区（名称与文字内容除外）。
  逐个改十二个图标不是界面该有的样子。
- **回车 / Delete 删除**：有选区时按回车、Delete 或 Backspace 会把选中的东西一起拿掉。
  光标在输入框里时这条不生效，所以打字时按回车不会误删。
- **图标填满磁贴**：`plate.bleed`（菜单里的「图标填满磁贴」）让图片直接铺满格子，
  不画卡片底、不留内缩，圆角照旧由磁贴圆角决定。
- **搜索栏和磁贴一样能拖**：一条栏几乎全是输入框，从前只有卡片边上那几像素能按。
  现在引擎图标、右端的按钮和卡片边缘都算把手（输入框除外，那里要能选字），
  指针落在能拖的地方会变成抓手。
- **圆形不再列出四个点不动的尺寸按钮**：圆形只有一格，那四个按钮从前是灰的，
  点下去什么也不发生——现在换成一句说明。

## 8. 一整块选区跟着手走，并且自己说会落在哪

选区被拿起来时，之前只在**整个位移都合法**的时候才跟着指针走：落点被别的东西占了，
`ok` 就是假的，于是在手底下的那几块磁贴原地不动，只有拒绝提示跟着指针滑。看起来
就是「手感很飘，图标不跟着指针」。

现在「被拿着」和「放不放得下」是两件事：

- **画在哪里**由指针决定——`carried` 取的是当前这一段位移本身（含 `px`/`py` 像素值），
  与 `ok` 无关。手里是几块，画面就跟着走几块，位置一律是各自原来的格子加上整段像素位移。
  这里也不能用「吸附后的格子 + 位移」：那样会把已经吸附的那部分算两遍，选区就会离手。
- **放不放得下**由下面的影子说——每一块磁贴下面都画一块落点提示，放得下是强调色
  （`.drop-target--group`），放不下是灰色拒绝态（`.drop-target--refused`），两种都是
  「一块磁贴一块影子」，跟着指针一格一格地滑。
- 松手时仍然只有两种结果：**整块选区落下去，或者整块不动**。

## 验证方式

`node tools/probe-dist.mjs` 会在无头浏览器里真的拖一遍，并把结果写成 JSON：

- `dragHeldStep` / `dragPastStep`：指针走半格、走八成格，松手后各前进整一格（就近吸附）。
- `dragSettledStep` / `dragLandsAfterSettling`：指针停住之后再松手，落点仍然成立。
- `dragTransitionOff` / `dragLifted`：按住期间 `transition-property` 为 `none`、`z-index ≥ 20`。
- `gridLinesShareOrigin` / `platesOffGrid`：网格线与画布同原点；没有磁贴落在格子之外。
- `barDragPickedUp` / `barDragStep` / `barDragMoved`：抓搜索栏的引擎图标能拿起整条栏并落位。
- `barDragNoPanel`：拖完之后引擎面板没有被那个补发的 `click` 打开。

`node tools/probe-dist.mjs --quick` 只跑拖一段（整条走查太长，中间卡一次就得重来）：

- `quickShowsLanding`：0.45 格、0.55 格、0.8 格三次拖动里，落点影子都在画面上（`quickUnder.preview` 等）。
- `quickStaysUnderHalf`：走不到半格，松手原地不动。
- `quickTakesNearest`：过半格，松手落到就近那格（`quickHalf.step` 是那一格）。
- `groupFollowed` / `groupMoved`：框出一块选区再拖，每一块的位移都正好等于指针走的像素。
- `groupHints` / `groupRefusedHints`：拖动时每块磁贴下面都有一块落点影子，放得下是强调色，放不下是灰色。
- `quickBarLifted` / `quickBarFollows`：搜索栏能不能被拿起（`plate--dragging`），以及拿起来之后是否跟着指针。
- `fieldNoneWorks` / `fieldCustom`：输入框底色选「透明」真的变透明、选「自定义」能用取色器。

无头环境里有两件事和真机不一样，探针里各补了一手，否则量到的永远是「没动」：

- `rafFires`：`requestAnimationFrame` 不画帧。探针用 `rafShimmed` 把它换成 16ms 的定时器，
  否则被拿起来的东西（画在帧回调里）在无头里永远停在原地。
- 过渡动画不推进。探针用 `frozen` 把 `transition`/`animation` 全部关掉，量到的是
  「画到哪里」，而不是「正在从哪里滑到哪里」。

「慢拖到贴边再松手」这一条没法在无头里重现——它是在真机上发现的，靠的是
**落点不再经过帧变量**这个结构性改动：无论画不画帧，松手读的都是最后一次指针位置。
